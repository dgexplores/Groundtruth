# Groundtruth

The 'Groundtruth' project ensures the reliability of AI retrieval systems through rigorous evaluation against a managed golden dataset.

## Run
```bash
python3 -m pytest tests/ -q                          # test suite (70 tests)
python3 -m evals.runner                              # retrieval matrix -> evals/reports/latest.json
python3 -m evals.runner --retrievers tfidf --headline tfidf:lexical   # single lane
python3 -m evals.runner --mode qa                    # exact-match QA scoring (stub model)
python3 -m evals.regression_gate evals/baseline_report.json evals/reports/latest.json --metric recall_at_10
python3 -m evals.regression_gate evals/baseline_report.json evals/reports/latest.json --metric tfidf_semantic_recall_at_10
```

The gate fails (exit 1) when the metric drops more than the 0.05 tolerance below baseline; a report missing the metric exits 2 instead of silently scoring it as zero. CI runs both lanes.

## Benchmark Table

Measured, not asserted: `evals/baseline_report.json` is generated by `python3 -m evals.runner` and committed as the gate baseline. Two retrievers × two query tiers, 50 docs / 50 queries per cell:

| Lane | recall@5 | recall@10 | Gate floor (recall@10) |
| :--- | :--- | :--- | :--- |
| TF-IDF, lexical queries | 1.0000 | 1.0000 | 0.9500 |
| **TF-IDF, paraphrase queries** | **0.7000** | **0.7000** | **0.6500** |
| Dense (all-MiniLM-L6-v2), lexical | 1.0000 | 1.0000 | 0.9500 |
| **Dense, paraphrase queries (headline)** | **0.9800** | **1.0000** | **0.9500** |

Setup: TF-IDF (scikit-learn) and dense embeddings (`sentence-transformers`, L2-normalized cosine), deterministic `(-score, id)` tie-breaks, one relevant document per query, `Recall@K` computed by `src.evaluator.evaluate_retrieval`. The two tiers are the same 50 documents: lexical queries reuse the answer's own vocabulary, paraphrase queries restate the question with no content-word overlap.

The 0.30 gap on paraphrase queries is the point: TF-IDF scores what it cannot match as zero, dense embeddings hold up. The headline cell (`dense:semantic`) is reported at the top level as `recall_at_5` / `recall_at_10`; every cell is also a flat key (`<retriever>_<tier>_recall_at_<k>`).

## Tradeoff
The gate threshold was set to a 0.05 tolerance to balance strict quality control with the reality of stochastic retrieval. We accept minor variance in semantic matches while blocking breaking changes in critical business logic queries.

## Honest Failure Notes

- **Lexical 1.00 measures the harness, not retrieval strength.** The lexical tier was authored so each answer appears in a natural sentence overlapping its query — a lexical retriever should pass it. That number verifies indexing, ranking, scoring and gating work end to end; the paraphrase tier is where retriever quality actually separates. Drop a real corpus into `evals/corpus.json` (documents + queries with `relevant_ids` and `tier`) to get a meaningful score.
- **TF-IDF cannot match paraphrases (measured 0.70, not 0.00).** Queries sharing no vocabulary with the relevant document score zero — except the ones that get lucky through stop words or near-duplicates in the corpus. The 0.70 is what's left after that luck; no synonyms or embeddings are involved.
- **One relevant doc per query** makes recall@K binary per query (hit rate). Multi-label corpora give partial credit.
- **Paraphrases are natural phrasing, not adversarial strings.** They were authored to read like a real user asking without content-word overlap with the answer, not tuned to force TF-IDF's number down. Whatever it measures is reported as-is.
- **Dense 1.00 at recall@10 is a 50-doc ceiling effect.** With only 50 documents and one relevant doc, recall@10 can barely fail (random baseline ≈ 0.20). The recall@5 column is the more discriminating number (0.98 dense vs 0.70 TF-IDF).
- **Bug the benchmark caught:** scikit-learn's default `token_pattern` drops single-character tokens, so the query `2 + 2` produced an empty vector and scored 0. Fixed via `TfidfRetriever.TOKEN_PATTERN` with a regression test in `tests/test_retriever.py`.
- **QA mode's 0.10 is a stub, not a model.** `simulate_llm` is a fixed lookup table; every report from that mode is labelled `stub:not-a-real-model`.
- **Model is cached in CI** (`actions/cache` on `~/.cache/huggingface`); first cold run downloads `all-MiniLM-L6-v2` (~90 MB).
